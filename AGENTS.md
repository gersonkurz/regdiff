# Repository Guidelines

## Project Structure & Module Organization

- `cmd/regdiff`: CLI entry point and version wiring.
- `diff/`: core diff/merge logic and .REG parsing helpers (tests live here).
- `internal/`: internal-only packages that support the CLI and diff logic.
- `docs/`: manual and usage documentation (see `docs/manual.md`).
- `dist/`: release artifacts generated by `just build-*` and `just release`.

## Build, Test, and Development Commands

Use `just --list` to see all recipes. Common ones:

- `just build`: build the CLI for your current platform.
- `just test`: run all Go tests (`go test ./...`).
- `just fmt`: format the codebase with `gofmt -w .`.
- `just vet`: run `go vet ./...`.
- `just check`: run `fmt-check`, `vet`, and `test`.
- `just build-all`: produce cross-platform binaries into `dist/`.
- `just release`: build and package release archives in `dist/`.

You can also build directly: `go build ./cmd/regdiff`.

## Coding Style & Naming Conventions

- Go style: run `gofmt` before committing; formatting is enforced by `just fmt-check`.
- Package names are lowercase; exported identifiers use `CamelCase`.
- Keep files and folders lowercase with underscores only when needed (Go standard).
- Prefer small, focused functions and avoid new dependencies unless necessary.

## Testing Guidelines

- Tests use Go’s standard `testing` package.
- Test files are named `*_test.go` and currently live under `diff/`.
- Run `just test` or `go test ./...` before submitting changes.
- To run a focused test: `go test -v -run TestDiff ./diff`.

## Commit & Pull Request Guidelines

- Commit messages are concise and imperative. History shows both plain messages and scoped conventional commits like `feat(regdiff): ...`; either is acceptable, but be consistent within a series.
- PRs should include:
  - a short summary and rationale,
  - any relevant command output (e.g., `just test`),
  - updates to `docs/` if CLI behavior or flags change.

## Architecture Overview

- `cmd/regdiff/main.go` parses CLI flags (both `/FLAG` and `-flag`) and orchestrates diff/merge/registry operations.
- `diff/` holds the comparison engine and parameter substitution (`$$VAR$$` from INI/XML/environment).
- `internal/registry/` contains Windows-only registry I/O with `//go:build windows` plus non-Windows stubs.
- `.REG` parsing uses `github.com/gersonkurz/go-regis3` via a local `replace` in `go.mod`.

## Security & Configuration Tips

- Registry writes (`/WRITE`, `/ALLACCESS`) require care and may need admin rights on Windows.
- `/REGISTRY` and live registry comparisons are Windows-only; keep cross-platform behavior in mind when changing code paths.
